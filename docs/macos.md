# macOS 桌面版

## 当前功能

Chainloom 使用 PySide6 原生桌面界面，启动后进入“钱包管理”。支持本地加密钱包库、批量导入、搜索与分组，以及 Ethereum、BSC、Base、X Layer 的原生币和 ERC-20 单次及批量转账。钱包管理无需联网。

转账页从本地钱包库选择发送钱包，确认后在本机签名、通过 RPC 广播。应用仅使用本地钱包，不加载浏览器引擎。历史版本的外部钱包交易记录保留查看能力；本地签名交易自动保存哈希，不再提供手动补录入口。

构建目标为 **macOS 13+、Apple Silicon（arm64）**。Intel Mac 需要在对应架构下另行打包和验证；未提供 Windows 安装包。

## 内置网络

当前内置 Ethereum（1 / ETH）、BSC（56 / BNB）、Base（8453 / ETH）和 X Layer（196 / OKB），均为主网。X Layer 使用官方 RPC `https://rpc.xlayer.tech`，备用 `https://xlayerrpc.okx.com`，浏览器为 `https://www.okx.com/web3/explorer/xlayer`；参数来源：[X Layer 官方网络说明](https://web3.okx.com/onchainos/dev-docs/xlayer/developer/build-on-xlayer/network-information)。当前确认数为应用的保守等待策略，不等同于 L1 最终性。

Sepolia 已从网络选择和 RPC 设置中移除。旧设置会先备份为 `settings.before-sepolia-removal.json`，再移除 Sepolia 的 RPC/资产配置；原来选中 Sepolia 时回到 Ethereum。旧交易记录仍可查看和复制，标为“Sepolia（已移除）”，不再创建、广播或联网刷新该网络的交易。

底层适用于标准 EVM 原生币与 ERC-20 转账，但每条网络仍需配置并验证链 ID、RPC、费用模型及确认策略；桌面端目前不提供任意新增网络入口。Solana 的地址、签名和交易协议不同，当前不支持 SOL 或 SPL 代币转账。

## 钱包管理

### 创建和解锁

点击“创建钱包库”，输入并确认 8–256 字符的密码。创建后自动解锁；下次启动默认锁定，需要输入相同密码。

密码无法找回。钱包库文件或密码遗失，可能失去访问所保存私钥的能力，请妥善保管。

### 批量导入

解锁后点击“批量导入”。可以从剪贴板粘贴，也可以选择 UTF-8 编码的 TXT / CSV 文件。

- TXT：每行一个 EVM 私钥，64 位十六进制，可带 `0x` 前缀；空行忽略。
- CSV：必须包含 `private_key` 列，可选 `name`、`address`，顺序不限；也支持“私钥、名称、地址”中文表头。
- CSV 的 `address` 如有填写，必须与私钥派生出的地址一致。
- 在“导入分组”下拉框中单选一个已有分组，本次新增的钱包统一归入该分组；不可在此输入新分组，需要时先在钱包管理中点击“新建分组”。
- CSV 不再支持 `group` / “分组”列。旧文件需删除该列后导入；重复钱包仍保留已有分组，不会被本次选择覆盖。
- 每批最多 1000 行、文件或内容最多 1 MB，每个钱包占一行。

CSV 格式示意（替换占位符后使用）：

```csv
private_key,name,address
替换为第一个私钥,运营钱包,
替换为第二个私钥,备用钱包,
```

导入内容默认隐藏，勾选“显示并编辑导入内容”后才会展示。取消或提交后会清空导入窗口的内容和编辑历史。原始文件和系统剪贴板仍由使用者管理，应用不会删除原文件或覆盖其他剪贴板内容。

点击“从剪贴板粘贴”仅载入内容，还需点击“校验并加密导入”才会开始导入。内容为空、超过大小限制或 CSV 结构有误时，导入窗口会明确提示；无内容时无法提交。

导入过程会在后台逐个校验、加密，显示处理进度。无效行及重复地址跳过，报告只显示行号与错误原因，不输出私钥。对于同一地址，本批重复和已存在的钱包均不会覆盖原钱包的名称、分组或私钥。

创建、解锁、锁定、导入结果及错误等钱包库操作提示统一使用弹窗，由用户手动关闭，不再定时消失；弹窗不阻止继续操作，新提示也不会自动关闭已有提示。导入期间保留处理进度条。余额查询的进度及结果直接在“资产余额”页签显示。导入结果分别列出新增、重复和无效数量，没有新增钱包时会明确显示“未导入任何新钱包”。有新增或重复钱包时，列表会清除原有搜索及分组筛选，显示全部钱包，避免导入结果被筛选条件隐藏。

整批加密完成后一次性写入。点击“取消操作并锁定”，或应用退出时，会取消尚未完成的导入；本批暂存内容不会部分写入，已有钱包不受影响。已经完成写入的批次会保留。

### 搜索与分组

- 搜索框匹配名称、地址和分组，不区分英文大小写。
- 分组下拉框可筛选指定分组。
- “新建分组”创建分组；“调整分组”支持多选钱包统一归组。
- “重命名”修改单个钱包名称。
- 双击任意钱包行，或右键该行选择“复制钱包地址”，复制该钱包的完整公开地址。复制后显示短暂的“复制成功”浮层，不弹窗。不提供私钥显示或导出。

钱包管理提供“钱包列表 / 资产余额”两个页签，共享上方的搜索及分组条件，切换时承接当前可见钱包的选择。EVM 私钥只需导入一次，地址无需按 Ethereum、BSC、Base 等网络重复创建。可切换到“资产余额”页签，或在批量转账选择钱包时查询所选网络的余额。单次转账页仍按所选网络和资产查询余额。

### 批量查询余额

解锁钱包库后，切换到“资产余额”页签。选择网络，按名称、地址或分组缩小范围。有勾选时，按钮显示“查询已选 N 个钱包”；未勾选时显示当前搜索、分组或全部钱包的数量。每次最多查询 1000 个钱包。余额条件仅筛选结果，未勾选时仍按上方搜索 / 分组确定查询范围。

点击“管理资产”可勾选要查询的 ERC-20 代币，原生币始终保留，也可直接添加并验证自定义代币。新增代币会保存到该网络的资产配置，转账页也可使用；查询资产的勾选范围在当前应用会话内保留。

可以选择筛选资产、填写最低余额、勾选“该资产余额 > 0”或“原生币余额 > 0”。点击列标题可排序，余额列按实际数值排序；“未查询”“查询失败”和真实零余额分别显示。失败时可点击“重试失败项”，仅重试当前搜索 / 分组中的失败项，保留成功项的数值、时间及区块；被余额条件隐藏的失败项也会重试。

查询只读取公开地址的链上余额，不解密私钥、不签名、不发送交易。一次完整查询使用同一区块，重试可能使用新区块；悬停余额可查看各项查询时间及区块，时间列使用北京时间，多次查询的同一钱包会标注“多次查询”。余额不会自动刷新。可随时停止查询并保留已完成结果，尚未完成的项显示“未完成”。切换页签或导航页面不会中止查询；切换网络会停止当前查询，展示对应网络在本次解锁期间保留的结果。锁定钱包库、退出应用后清空查询快照，不保存到磁盘。

钱包列表负责整理钱包，资产余额页负责查询与筛选；其中的勾选仅确定余额查询范围。批量转账统一从侧边栏菜单进入，在转账页选择钱包并填写清单。批量转账中的选钱包窗口仍支持余额查询与筛选，网络固定为当前批次网络；每批最多 100 笔，被筛选隐藏的钱包不会加入清单。原生币余额大于零不代表足以支付手续费，发送前仍需重新校验。

多对一及多对多模式点击“添加一行”时，发送钱包默认为空，需要自行填写地址或从钱包库选择；一对多模式使用明确选择的统一发送钱包。

### 锁定

点击“锁定钱包库”会禁用钱包操作、隐藏并清空页面中的钱包列表和筛选内容，停止余额查询并清空各网络的余额快照，关闭本页打开的导入或密码等弹窗。闲置 5 分钟后自动锁定，退出应用时也会锁定。

锁定期间，正在执行的一次加密运算可能需要短暂时间完成；后续操作会被中止，解锁前不能再次导入或修改。重新解锁只验证钱包库密码，不会一次性解密所有已保存私钥。

锁定会停止尚未完成的本地签名；重新解锁后需重新预览。已签名或已发送的交易会保留记录，锁定和退出不会撤回交易。

## 单次转账

1. 创建或解锁钱包库，批量导入发送钱包。
2. 进入“转账”，选择网络、本地钱包与资产。未解锁时可在此点击“解锁钱包库”。
3. 填写完整收款地址与数量，点击“下一步：预览转账”。
4. 等待余额、代币精度、Gas 模拟和费用预估完成，核对网络、完整发送/收款地址、资产合约、数量与执行手续费上限，点击“确认并发送”。取消不会签名或发送。
5. 程序仅解密所选钱包，在本机签名并广播，随后切换到“交易记录”。在此查看哈希和链上确认状态，或打开对应区块浏览器。

交易列表显示时间、网络、数量、状态、发送地址、收款地址和交易哈希。地址及哈希缩略显示，鼠标悬浮可查看完整内容；双击或右键复制对应字段，也支持选中单元格后按 Cmd+C（Windows/Linux 为 Ctrl+C）。复制内容为完整原值，成功后在窗口右上方显示绿色对勾的“复制成功”轻量浮层，1 秒后自动消失，不抢占键盘焦点，也不阻挡鼠标操作；尚未获得哈希时不会复制占位符。交易时间、钱包导入时间和复制详情统一显示北京时间（UTC+8），底层时间戳继续按 UTC 保存。

确认页不会自动关闭或自动发送。

## 批量转账

### 创建清单

侧边栏“批量转账”提供三种模式：

- 一对多：选择统一发送钱包，逐行填写收款地址和数量。
- 多对一：填写统一收款地址，从本地钱包库按搜索或分组勾选发送钱包，逐行填写数量。
- 多对多：逐行指定本地发送钱包、收款地址和数量。

切换模式会清空当前正在编辑的转账清单，需要重新添加或导入明细，避免将旧模式的数据转换成不同的付款请求。已保存的批次和交易记录不受影响。

每批限 1–100 笔，只使用一条网络和一种资产。默认手动填写明确数量，通过侧边栏“批量转账”进入，在该页选择本地钱包并编辑清单。

### 按余额归集

多对一模式下，先填写统一收款地址并选择发送钱包，再点击“按余额归集”。按钮计算当前清单的全部行（与删除用的勾选无关），将可转数量填入清单，不创建批次、不签名、不发送交易；计算后的数量仍可手动修改。

- 原生币：可转数量 = 计算时余额 − 执行手续费预留 − 每钱包额外预留。
- ERC-20：使用全部代币余额，按代币实际精度计算；手续费从原生币支付，必须足以覆盖执行手续费和额外预留。
- 执行手续费按当前网络费率和实际收款地址估算，Gas 保留 20% 余量；EIP-1559 使用当前费用上限，legacy 使用节点 Gas 价格。不固定假设每笔都是 21,000 Gas。
- “每钱包额外预留”以原生币计价，默认 0，除执行手续费外额外扣留。Base / X Layer 另收数据费，必须填写大于 0 的额外原生币预留；该输入是用户预留预算，不是数据费报价。

重复的发送钱包、零余额、手续费不足、待确认交易及模拟失败会逐行显示；失败行保留在清单中并清空数量，不会自动跳过。请修正、移除失败行或手动填写后再预览。

计算在后台显示进度，可点击“停止计算”；停止或计算期间锁定钱包库，不会把旧结果填入清单。计算结果是当时的余额与费用快照，修改网络、收款地址、钱包清单或预留后应重新计算。网络切换会将额外预留重置为 0，避免将不同原生币的数量混用。

回填后仍需点击“下一步：预览并校验”，核对固定数量与手续费，再确认发送。执行及恢复仍按已确认的固定数量逐笔处理，余额或费用变化不会擅自增加转账金额；费用超过确认上限或余额不足时暂停，需重新核对。

支持手动添加、勾选后删除选中行、将统一数量应用到全部行，以及导入 UTF-8 CSV。导入内容追加到当前清单，最多 1 MB。

列表首列使用勾选框，表头方框用于全选 / 取消全选当前页；目前清单为单页，滚动区域内的行也包含在内。部分勾选时表头显示半选状态。只有勾选的行会被“删除选中行”删除，行高亮不代表勾选；新增或导入的行默认不勾选。勾选仅用于删除，不改变转账范围，预览和执行仍包含清单中的全部明细。全选后删除即可清空编辑清单，无需“新建批次”按钮。没有已保存批次时隐藏历史选择入口；保存首个批次后显示“查看历史批次”下拉框，可选择历史任务，也可选择“编辑转账清单”返回录入。

可下载只有表头的 CSV 模板：

```csv
sender,recipient,amount
```

每行填写完整公开地址和普通小数数量，不能包含私钥。表头也支持 `from` / `to` 及“发送地址、收款地址、数量”。一对多可仅导入 `recipient,amount` 两列，多对一可仅导入 `sender,amount` 两列；省略的一侧使用页面统一设置。无表头的两列表格同样按当前模式解释，多对多需要三列。

### 预览与确认

点击“下一步：预览并校验”，检查地址、代币精度、发送钱包归属、已有待确认交易，以及每个钱包累计转账数量和全部执行手续费所需余额。所有错误必须修正后重新预览，系统不会自动剔除错误行。

填写清单时，“校验结果”列会实时显示地址核对结果：地址格式、校验和或零地址错误显示为红色；自转账、疑似重复付款和重复收款地址显示为黄色，并显示已解锁钱包库中的收款钱包名称。多对一归集中正常的重复收款地址不提醒，但完全重复的付款仍需核对。可勾选“提醒非本地收款地址”（默认关闭）；非本地只表示地址不在当前钱包库，不代表无人持有私钥。

确认页展示完整地址、逐笔数量、转账总数量、每笔和累计执行手续费上限，以及各发送钱包支出汇总。地址提醒会按行展示并汇总，需要勾选“已核对上述地址提醒，仍按清单分别付款”后才可开始；重复行不会自动合并。所有地址错误仍会阻止发送。按余额填充和恢复批次也会重新核对地址。L2 可能另收 L1 数据费，需保留原生币余量。

一次确认仅授权该批清单内的付款及对应执行手续费上限。每行独立生成交易，部分成功无法整体撤回。未确认的编辑清单尚未保存为任务；点击确认后，批次和固定逐笔请求编号才持久化到 `transactions.sqlite3`。

### 执行、暂停与恢复

当前一个应用实例同时只执行一个批次，并与单次转账互斥。程序逐笔检查、签名和广播，上一笔达到网络配置确认数后才继续下一笔，因此主网大批次可能耗时较长。每笔执行前重新获取 nonce、检查余额及费用，不复用已过期的单笔预览。

执行中可切换页面，批次仍继续；详情展示成功、失败和取消数量、计划数量、状态和哈希。单笔交易记录的提示中包含所属批次，可在地址或哈希上右键选择“查看所属批次”。双击批次详情字段可复制完整内容。

- “暂停后续发送”：阻止下一笔签名，已经进入签名或广播的操作可能完成；已发送交易仍需查询。
- “预览并继续未发送任务”：解锁钱包库，重新预览剩余任务并确认后继续。已保存签名的任务不会重新签名。
- “结束批次”：取消尚未签名的任务，保留已经签名或发送的交易及其结果，不撤回链上交易。
- “重播选中原交易”：用于已签名或结果不明确的交易，只广播原签名字节，保持原哈希，不创建新付款。
- “导出结果 CSV”：导出本批网络、资产、逐笔请求编号、地址、数量、状态、哈希和错误，不包含私钥或原始签名交易。

费用超过确认上限、余额不足、链上失败、RPC 异常或发送结果不明确时暂停批次。失败的链上交易可能已经扣除 Gas；继续时只处理尚未发送的行，不会自动重新付款。发现正常待打包交易时继续等待确认，不因缺少回执而再次签名。

钱包库锁定（包括闲置 5 分钟自动锁定）会停止后续签名。应用退出或重启后批次保持暂停，可从“查看历史批次”选择并核对结果，再手动继续；不会自动恢复付款。暂停或结束的批次在选中查看时继续查询已有待确认交易。不要因超时新建同一批清单重付。

## 交易恢复

签名后、广播前将完整签名交易和哈希持久化到本地 SQLite。网络断开、响应丢失或应用退出后，交易记录仍可查询。不因 RPC 查不到回执就判定失败，也不会自动重新签名或创建新付款。

| 状态 | 处理方式 |
| --- | --- |
| 已签名，等待广播 | 查询状态，必要时重播原交易 |
| 已提交 / 结果待确认 | 刷新状态，切勿新建同一笔付款 |
| 链上确认中 | 等待配置的确认数 |
| 转账成功 | 回执成功且达到确认数 |
| 链上执行失败 | 回执失败且达到确认数，Gas 仍可能扣除 |

“重播原交易”仅再次广播已保存的同一份签名字节，保持原哈希和 nonce；已上链的交易不会再次广播，也不需要再次解锁。签名、已提交、结果不明确或确认数不足的请求会阻止同一网络、同一钱包的新付款。不要切换数据目录或用其他工具绕过限制。

本地交易在广播前自动保存哈希，不再提供手动补录哈希的按钮、输入流程及写入接口。已有外部钱包记录仍保留；已有哈希的记录可继续核验并查询状态。

默认每 7 秒查询待确认交易，也可手动刷新。查询会核对回执所在区块哈希；确认数达到阈值不等于共识最终性。

交易列表增加勾选框及“全选”。未勾选记录时，“刷新链上状态”和“重播原交易”均不可点击。行高亮仅供查看、复制和打开浏览器，与勾选无关；刷新列表后按交易编号保留勾选，新出现的交易不会自动勾选。

“刷新链上状态”只查询点击时勾选的记录。无哈希和已移除网络的记录会跳过。刷新期间按钮显示进度状态，完成后弹窗报告查询、状态变化、查询失败及跳过数量；状态未变化也会提示。单条查询失败不会阻止其余勾选记录刷新，查询失败不代表链上转账失败。后台轮询进行中时，手动请求会排队，并保留点击时的勾选范围。

“重播原交易”同样只处理点击时勾选的记录，确认后逐笔检查。已成功、已失败、正在链上确认、非本地签名或已移除网络的交易会跳过，完成后报告处理、异常和跳过数量。重播保持各笔原签名、哈希和 nonce，不创建新付款或提高手续费；执行前仍会查询链上状态，避免重播已上链的交易。

## 费用与网络

数量使用字符串和最小单位整数，ERC-20 精度从合约查询。发送前重新核对链 ID、nonce、余额、模拟结果、Gas 和费用字段。预览有效期为 120 秒；条件变化会停止发送，需要重新预览。

EIP-1559 与 legacy 费用模式自动选择，Gas 估算增加 20% 余量。展示的是执行 Gas 费用上限。Base、X Layer 等 L2 可能另有 L1 数据费，余额需留出余量。特殊代币可能收取转账税，交易成功不承诺收款余额精确增加输入数量。

默认使用内置公共 RPC，失败时尝试备用地址；设置中可覆盖为 HTTPS RPC，本机测试节点允许 HTTP。公共节点可能限流，需支持 `pending` 状态的查询、模拟和 Gas 估算。

## 本地数据

通过“设置 → 打开本地数据文件夹”查看钱包库所在目录。开发时可用 `--data-dir /绝对路径` 指定独立数据目录。主要文件包括：

- `wallets-vault.sqlite3`：逐个加密的 Ethereum V3 keystore；名称、地址、分组是明文索引。
- `transactions.sqlite3`：交易参数、哈希、状态、可重播的签名交易，以及批次清单、逐笔请求编号和费用确认上限。
- `settings.json`：网络与自定义资产；RPC URL 可能含凭据。旧版连接配置字段会在读取时自动移除。
- `desktop.lock` / `transfer.lock`：实例和签名广播互斥锁。

### 加密与存储边界

- 私钥使用标准 Ethereum V3 keystore，采用 scrypt `N=262144, r=8, p=1`，逐个加密保存；签名时只解密所选钱包。
- 密码通过加密的随机校验值验证，磁盘不保存明文密码。
- 名称、地址、分组、导入时间为 SQLite 明文索引，并非整个数据库加密。
- 新钱包库文件权限为 `0600`，创建时不覆盖已有钱包库。
- 交易数据库保存可重播的签名字节，应与钱包库一起作为敏感本地数据保护。

私钥只在本机解密用于签名，不发送给 RPC、日志或云服务，也不通过 Qt 信号传回界面。锁定会清理应用持有的解锁状态及可变密码缓冲区；Python、Qt 和操作系统仍可能保有临时内存副本，不能将其视为取证级内存擦除。恶意软件已控制的电脑不在本地加密所能保护的范围内。

### 备份与恢复

进入“设置 → 备份与恢复”，无需先解锁钱包库。适用于换机、重装系统、升级前留存副本，以及本地数据丢失后的恢复。

创建备份：

1. 点击“创建加密备份”，选择新的保存文件名，后缀为 `.chainloom-backup`。已有文件不会被覆盖。
2. 输入并确认 8–256 字符的备份包密码，点击“创建加密备份”。备份包密码用于打开备份，钱包库仍保留原密码。
3. 应用暂停后续发送、锁定钱包库、停止余额查询并等待后台任务结束，然后保存钱包库、交易及批次记录和已有的 `settings.json`。已经签名或发送的交易会保留；尚未完成的导入会取消，已提交的数据会包含在备份中。
4. 等待加密、保存及回读校验完成。将备份放到独立存储设备，分别保管备份包密码与钱包库密码。取消或失败不会覆盖已有备份。

恢复备份：

1. 点击“恢复备份”，选择备份包，输入备份包密码，点击“校验并预览”。此操作也会暂停后续发送并锁定钱包库。
2. 查看备份时间（北京时间）、应用版本、钱包与分组数量、交易与待核对交易数量、批次与未完成批次数量，以及是否包含设置。密码错误、文件损坏和不支持的数据版本会阻止恢复。
3. 选择恢复位置，确认“恢复后先核对链上状态”，点击“恢复到新目录”。应用在所选文件夹下新建 `Chainloom-Restored-日期-随机编号` 目录，原数据保留；失败或取消会清理本次未完成的恢复目录。
4. 完成后可选择立即切换使用恢复的数据。应用重新打开主窗口，下次从相同入口启动也继续使用该目录。钱包库保持锁定，使用备份时的钱包库密码解锁；所有未完成批次保持暂停，已保存的签名、交易哈希和固定请求编号保留。
5. 先查询最新余额、刷新待确认交易并核对批次，再重新预览并确认剩余任务。恢复本地记录不会撤回链上交易；备份之后发生的交易可能不在记录中，不能直接重建同一付款。

切换后的目录选择保存在原启动数据目录的 `active-data.json`，其中只包含本地目录路径，不包含密码。启动时会同时锁定原启动目录和当前目录，防止两个实例操作同一套数据。所选磁盘不可访问时会明确报错，不会自动建立空钱包库；移动恢复目录后需同步更新该路径。使用 `--data-dir` 启动其他数据目录时，该入口单独记录自己的选择。恢复完成后若选择暂不切换，可稍后使用 `uv run chainloom-desktop --data-dir /恢复目录的绝对路径` 打开。

备份使用固定参数 scrypt（`N=262144, r=8, p=1`）派生密钥，并以 AES-256-GCM 加密和认证整个备份包；包内记录文件大小和 SHA-256 校验值。私钥始终以原有 keystore 密文复制，不解密、不导出明文。SQLite 使用包含已提交 WAL 数据的独立快照。临时快照放在权限为 `0700` 的临时目录，文件为 `0600`，操作结束后清理；备份、恢复文件和目录也设置本机访问权限。备份不包含日志、锁文件或原始导入文件。单文件最多 64 MiB，数据总量及加密包最多 128 MiB。

新增钱包或修改钱包库密码后应重新备份；旧备份仍使用备份当时的钱包库密码。若选择手动备份，应先锁定钱包库、退出应用并等待进程结束，再复制完整钱包库、交易数据库及设置文件。

## 错误日志

macOS 按桌面应用惯例将日志保存在 `~/Library/Logs/Chainloom/chainloom.log`，与钱包库和交易数据库分开。无需手动创建目录，应用启动时自动建立。

打开“设置 → 打开日志文件夹”即可定位；设置页也显示日志文件的完整路径，错误弹窗会提示查看日志。排查时先重新启动更新后的应用，再复现问题；修改前的异常不会自动补写。

日志时间使用北京时间（+0800），包含进程/线程、后台任务编号、操作步骤、Python 异常类型和堆栈位置；记录 RPC 连接失败、本地签名、交易广播及状态查询中的异常，包括广播结果不明确但程序已保留交易的情况。主线程和独立 Python 线程的未处理异常同样记录。正常退出取消任务不作为错误。

应用日志文案使用中文，日志级别保留标准的 INFO / WARNING / ERROR。异常同时记录中文操作说明、脱敏后的原始错误文本、RPC 错误码及关联异常堆栈；第三方原始错误保留原语言，便于对照排查。钱包操作中的密码在异常传播到后台任务前脱敏，包括被重新包装的底层异常。日志不输出密码、私钥、助记词、keystore、完整 RPC URL、已签名交易、二进制密钥、源码行或局部变量。

关键操作以 INFO 记录：设置保存及变更前后内容、钱包库创建/解锁/锁定、批量导入结果和新增钱包的公开信息、分组创建、钱包重命名及分组调整、转账预览、保存签名交易、广播、重播及状态变化。RPC 配置只保留协议、主机和端口，认证路径与查询参数隐藏。转账记录保留网络、公开地址、数量和完整公开交易哈希；状态未变化时不重复打印。

单文件上限 2 MiB，保留 5 份轮转备份（`chainloom.log.1` 至 `.5`），总量约 12 MiB。macOS 日志目录权限为 `0700`，日志和备份文件为 `0600`，不上传日志。

Windows 路径为 `%LOCALAPPDATA%/Chainloom/Logs/`，Linux 路径为 `$XDG_STATE_HOME/chainloom/logs/`（缺省 `~/.local/state/chainloom/logs/`）。开发测试可用 `--log-dir /绝对路径` 覆盖目录，设置页显示和打开的路径也会同步改变。

## 从源码运行

```sh
uv sync --locked
uv run chainloom-desktop
```

macOS 源码启动会在当前虚拟环境的 `.chainloom/Chainloom.app` 中创建专属启动程序，使 Dock 使用 Chainloom 名称和图标；仍使用当前源码和依赖。更新 Python 或重建虚拟环境后会自动刷新启动程序。

可用 `--data-dir /绝对路径` 指定独立开发数据目录。日常使用请保留相同目录，以便恢复钱包与交易记录。当前本地转账流程不需要 Node 或联网加载 JavaScript。

`Ctrl+C` / `SIGTERM` 会停止后续操作、关闭弹窗并等待当前工作结束，随后释放实例锁。RPC 连接和读取超时各为 3 秒，禁用隐式重试；已签名或已发送的交易不会因退出撤回。

## 构建 macOS 安装包

```sh
uv sync --locked
uv run python scripts/build_macos.py --dmg
```

输出 `dist/Chainloom.app` 与 `dist/Chainloom-0.1.0-arm64.dmg`。构建无需 Node 或 JavaScript 资源。构建不会上传或公证。

默认使用本地 ad-hoc 签名；正式分发仍需 Developer ID 签名与 Apple 公证。可通过 `CHAINLOOM_SIGNING_IDENTITY` 指定现有签名身份，使用 `notarytool` 提交公证并 staple 凭证，再验证 Gatekeeper。账号和签名凭据不应写入仓库。
